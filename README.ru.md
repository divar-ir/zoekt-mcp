## Обзор

Сервер интегрируется с Zoekt — поисковым движком, оптимизированным для репозиториев кода. Zoekt использует триграммное индексирование, что подходит для поиска по большим кодовым базам и удобно для AI-ассистентов, которым нужно находить и понимать код.

## Возможности

- **Поиск по коду** — триграммный индекс Zoekt
- **Расширенный язык запросов** — регулярные выражения, фильтры по файлам/языкам, булевы операторы
- **Обзор репозиториев** — поиск по имени и структура каталогов
- **Чтение содержимого** — файлы и деревья каталогов из индекса
- **Заточено под LLM** — поставляется с гидом по построению запросов

## Требования

- **Инстанс Zoekt** — доступ к запущенному поисковому серверу Zoekt. См. [документацию Zoekt](https://github.com/sourcegraph/zoekt#installation).
- **Python 3.13+** — для запуска сервера (требование `pyproject.toml`).
- **UV** (рекомендуется) — современный менеджер пакетов Python для управления зависимостями.

## Установка

```bash
# Клонировать репозиторий и перейти в него
git clone <repo-url> zoekt-mcp
cd zoekt-mcp

# Установить зависимости (создаст .venv)
uv sync
```

После этого доступны два режима запуска:
- **stdio** — для встраивания в MCP-клиенты (Claude Code, Cursor, и т. п.);
- **HTTP/SSE** — как самостоятельный сетевой сервер.

## Переменные окружения

| Переменная | Обяз. | По умолч. | Описание |
|---|:---:|---|---|
| `ZOEKT_API_URL` | ✅ | — | URL вашего инстанса Zoekt |
| `ZOEKT_API_LOGIN` | — | — | Логин basic-auth (если инстанс требует авторизации) |
| `ZOEKT_API_PASSWORD` | — | — | Пароль basic-auth |
| `ZOEKT_VERIFY_SSL` | — | `true` | Проверка SSL-сертификата (`false` — для самоподписанных) |
| `MCP_TRANSPORT` | — | — | `stdio` для запуска на stdin/stdout. Обычно задаётся MCP-клиентом в его конфиге, а не в `.env` |
| `MCP_SSE_PORT` | — | `8000` | Порт SSE-сервера |
| `MCP_STREAMABLE_HTTP_PORT` | — | `8080` | Порт HTTP-сервера |

> Авторизация включается только если заданы **обе** переменные `ZOEKT_API_LOGIN` и `ZOEKT_API_PASSWORD`. Если хотя бы одна отсутствует — подключение выполняется без авторизации.

Шаблон переменных — в [`.env.sample`](.env.sample). Скопируйте его в `.env` и заполните значениями (`.env` читается через `python-dotenv`).

## Подключение к AI-клиентам

### Claude Code (stdio, актуальный метод)

Сервер запускается в режиме stdio через обёртку **`run-stdio.sh`**, которая сама переходит в корень репозитория и выполняет `python -m src.main`. Это важно: **Claude Code (вплоть до 2.1.x) не применяет поле `cwd`** из конфигурации stdio-MCP — процесс-ребёнок наследует рабочий каталог родительской сессии. Без обёртки `python -m src.main` не находит пакет `src/` и падает с `MCP error -32000: Connection closed` во всех сессиях, чей cwd не совпадает с корнем репо.

Добавьте сервер в `~/.claude.json` (глобально, в `mcpServers`) или в `.mcp.json` проекта:

```jsonc
{
  "mcpServers": {
    "zoekt-mcp": {
      "type": "stdio",
      // Абсолютный путь к обёртке. cwd клиент не применяет — обёртка cd'ит сама.
      "command": "/home/user/path/to/zoekt-mcp/run-stdio.sh",
      "args": [],
      "env": {
        "MCP_TRANSPORT": "stdio",
        "ZOEKT_API_URL": "https://code.example.com/",
        "ZOEKT_API_LOGIN": "search",
        "ZOEKT_API_PASSWORD": "ваш-пароль",
        "ZOEKT_VERIFY_SSL": "false"
      }
    }
  }
}
```

После изменения конфигурации перезапустите сессию или выполните `/mcp` → выбрать `zoekt-mcp` → **Reconnect**.

> Если нужно увидеть реальный stderr сервера (по умолчанию Claude Code его скрывает), запустите сессию с флагом `claude --debug`, затем `/mcp` → Reconnect.

### HTTP / SSE

Без stdio сервер поднимает HTTP и SSE транспорты одновременно:

```bash
uv run python src/main.py
# → streamable-http на :8080/zoekt/mcp, SSE на :8000/zoekt/sse
```

Эндпоинты здоровья: `GET /health` (liveness) и `GET /ready` (readiness).

### Cursor

После запуска сервера (например, по HTTP) добавьте в `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "zoekt": {
      "url": "http://localhost:8080/zoekt/mcp/"
    }
  }
}
```

### Docker

```bash
# Собрать образ
docker build -t zoekt-mcp .

# Запустить с портами по умолчанию
docker run -p 8000:8000 -p 8080:8080 \
  -e ZOEKT_API_URL=http://your-zoekt-instance \
  zoekt-mcp

# Со своими портами
docker run -p 9000:9000 -p 9080:9080 \
  -e ZOEKT_API_URL=http://your-zoekt-instance \
  -e MCP_SSE_PORT=9000 \
  -e MCP_STREAMABLE_HTTP_PORT=9080 \
  zoekt-mcp
```

## MCP-инструменты

Сервер предоставляет три инструмента:

### 🔍 `search`
Полнотекстовый поиск по индексу Zoekt с поддержкой расширенного синтаксиса: регулярные выражения, фильтры по файлам и языкам, булевы операторы.
- `query` (обязательный) — поисковый запрос;
- `limit` (опциональный, по умолчанию 30, диапазон 1–100) — число результатов.

### 📖 `search_prompt_guide`
Генерирует контекстный гид по построению эффективного запроса под конкретную задачу. Рекомендуется вызывать первым, если вы не знакомы с синтаксисом Zoekt.
- `objective` (обязательный) — что нужно найти.

### 📂 `fetch_content`
Возвращает содержимое файла или структуру каталога из проиндексированного репозитория.
- `repo` (обязательный) — путь к репозиторию, например `github.com/org/project`;
- `path` (обязательный) — путь к файлу или каталогу внутри репозитория (пустая строка — корень).
